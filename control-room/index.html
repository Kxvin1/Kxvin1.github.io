What changed

Give it eyes. Then take everything off the human's desk that does not need a human.

My day job is keeping a suite of 1,600 automated end-to-end (E2E) tests running against a large product that ships features fast. When the product changes, E2E tests break, and someone works out why. The AI was good at the repair and blind to everything else, so I was the courier.

A broken suite used to hold the client's release for a week. Now it is green by lunch, so they ship daily.

Before

One broken E2E test. Ten hand-offs.

  1. Me, reading the failure on a dashboard
  2. Me, copying the error into a chat
  3. It guesses at a cause it cannot see
  4. Me, screenshotting so it can see
  5. It writes a fix
  6. Me, pasting the fix and running it
  7. Me, waiting, then copying the next error
  8. Repeat until it passes, or the day ends

After

One broken E2E test. Two hand-offs.

  1. It reads the failure and the video itself
  2. It opens the product and confirms what changed
  3. It writes the fix and runs it twice to prove it
  4. It lands on a board, marked ready, with the reason
  5. Me, pasting and running
  6. Me, confirming it passed

The part that compounds

It files its own bugs and learns from its own mistakes

The system is not finished and was never meant to be. It gets a little better every day, and most of that improvement is not mine.

A tracker that fills itself

I can file a bug or an idea with one key. The interesting half is that the AI files them too, on its own, from whatever it ran into that day: a rough edge in the tooling, a gap it noticed, a bug in my own scripts.

Every row says who raised it, so I always know which are mine and which it brought to me. I keep, reprioritize or bin them.

When something goes wrong

It writes the lesson down

If I correct it, or it repeats a mistake, the rule goes into a permanent file that same day.

Not a note for later. Part of how it works from then on.

Every evening

It runs its own retro

It re-reads the day, finds what it got wrong, and writes down anything the live capture missed.

It also scores its own past predictions to see where it was overconfident.

Then it locks the door

It adds a check against itself

A lesson becomes an automated check, and the check has to fail on purpose first.

If it cannot catch a planted mistake, it is not trusted.

It keeps a ledger

One row per lesson

Every lesson is a row that says what happened, where the rule now lives and what proved it. The rows are read back into the next session before it starts.

If the same correction lands twice, the count goes up and the capture gets fixed, not repeated.

It audits its own rulebook

Learning is not more text

Once a week it measures the rules it loads every session, lists anything said twice so the duplicates get merged or retired, and checks that its memory index still matches the files.

The rulebook gets shorter and sharper, not longer.

It shows me the trend

A page for what it learned

What it learned, healed, improved and fixed, on a fourteen day trend, with a countdown to the next retro.

If something needs me, that list comes first and each item carries the exact prompt to hand back.

The practical effect is that the same problem does not come back, and everything it learns about the product is written down where the next investigation will find it. The bigger the suite gets, the more that matters.

The part that watches itself

It keeps its own books

Since September it records what it was asked, what it answered, what each answer cost and how much disk it takes up. None of that is typed by hand. It is derived from the session transcripts, so it cannot drift from what actually happened.

An inbox of everything I asked

One row per request, newest first, with a status the page works out for itself: done, your move when the last reply handed me an action I have not answered yet, running while the session is still writing.

Pick a row and the whole exchange opens beside it, with a line at the bottom for what it produced: the tracker rows, the files it named, the asks it left me.

A second view lays the day out as a timeline, with a batch of work drawn as one band.

What it cost

Every dollar has a line item

Tokens and cost per day and per model, and what share went to re-reading history versus writing answers. Each saving I try is measured, then kept or dropped on the number.

One rule sits above all of it: thinking is never cut to save money. Only waste is.

What it takes up

Every large file has a rule

A storage view names the biggest files and folders, who writes each one and which retention rule covers it. One script prunes everything on schedule.

If a cleanup did nothing useful, a red banner says so.

How it hands off

It briefs its own next session

A gauge weighs how much context a session has used against what is still in flight and recommends a fresh start. At every close it rewrites a hand-off from live state.

The next session reads it before my first word.

The part that makes it trustworthy

The AI cannot mark its own homework

An AI will tell you the work is ready, because it believes that. So "ready" here is not an opinion. It is a gate, and the evidence has to already exist.

The gates live in the core, so every specialization inherits them before it has written a line of its own.

  • Two clean runs recorded on my machine
  • One clean run on the real E2E test machines
  • All three against the same version of the code
  • The run id written onto the card, so I can check it
PROVENotherwise the card cannot move
Wide, not one at a time

Twenty E2E tests on twenty machines

Proof runs go out in parallel on the real infrastructure, each E2E test on its own machine, measured at twenty at once with no slowdown. A whole batch proves itself in the time one E2E test used to take.

That is what makes a same-day release possible instead of a weekly one.

Merged, not overwritten

Teammates' changes in five seconds

Before it edits a shared file it pulls the latest copy and merges three ways: their version, its own edits, the last known base.

Its edits land on top of theirs, and only a same line overlap becomes a conflict for a human to place.

Re-checked, never re-written

Open bugs get re-verified on command

One key re-runs the E2E tests behind every open bug report and records whether each bug still reproduces, run id attached. It never edits a report.

If a bug's status changed on the other side, a red flag stays up until I have seen it.

One core, many specializations

The engine is the same. Only the specialization changes.

One core holds everything that does not depend on the job. Each job adds a thin layer that says what its evidence is, what "proven" means, and where the human gate sits. Whatever the work is, the AI gathers the evidence, does the work and proves it. You keep the one step that is hard to undo.

A code review queue could be next
open the PR→ first-pass review→ nits fixed, tests run→ approve

Every PR reaches you already cleaned up, with the tests green. You spend your review on the design call, not on naming and formatting.

An AI eval loop could be next
change the prompt→ run the evals→ score and diff vs last→ promote

Nothing ships on vibes. A prompt cannot be promoted until the scores are recorded against that exact version, and regressions surface before you look.

A support desk could be next
reproduce it→ find the cause→ write and prove the patch→ release

Tickets land already reproduced with a proven fix attached. The ones that turn out to be user error never reach an engineer at all.

A hiring pipeline could be next
collect the work samples→ draft the prep notes→ chase the scheduling→ every judgment call

You walk into each conversation already briefed, and the admin trail chases itself. No screening decision is ever made for you.

Cartograph building next
open a PR→ read the change→ write the review→ decide

Read what your coding agent changed. A pull request becomes a page a person can read, every sentence pointing at its code and marked whether it was run, only read, or still needs you. It never fails a build; a review is not a gate.

Every row above has the human gate in a different place, because that is a choice, not a limitation. Move it earlier if the work is risky, later once you trust it. Cartograph is the one I am building next.
